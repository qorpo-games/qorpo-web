TAMITOS directory records: source dates and provider confirmation

Q
QORPO Studio27 November 2026 · 4 min read

A TAMITOS directory record can show when source data was observed, when the register was updated and when TAMITOS loaded it. Individual provider confirmation is a separate status. A recent import date does not, by itself, establish that a service has a free appointment or has confirmed every detail.

That distinction is useful before a family makes a call or plans a journey. The directory helps organise public information. The next decision should follow the specific field, date and confirmation shown, rather than treating one fresh-looking date as proof of everything.

Read the service, not only the organisation

Start with the actual service record in the TAMITOS directory. Its name, kind, service form and location help establish what the entry describes.

One organisation can appear through more than one service. Those entries are not automatically duplicate organisations to be counted as separate providers, nor are they interchangeable offers. Read the service type alongside the name.

For the wider product context, our TAMITOS website update describes recent directory presentation work. This guide focuses on how to interpret a record today.

Separate three dates

The current implementation can display source observation, register update and import dates when those fields exist. Each describes a different event in the information chain.

An observation date concerns the data's reference point. A register update concerns the source. A fetched date concerns TAMITOS loading the record. The interface does not make an older source observation become today's observation merely by importing it again.

If a date is absent, do not supply one from another field. Missing information is uncertainty to resolve, rather than evidence that something happened today or never happened at all.

Provider confirmation has its own scope

The directory displays provider confirmation separately from public-register provenance. Its implementation can identify selected confirmed fields and a confirmation date, with a later review due date.

Read the fields that were confirmed. A confirmed telephone number is not automatically confirmation of capacity, clinical suitability or a particular intervention. Do not expand a limited confirmation into a broad endorsement.

The interface also distinguishes a confirmation that needs renewal and a source change that requires checking. Those states are more informative than a single permanent “verified” label would be.

Use the original source link

A record can link to its original source and the provider's own website. Those destinations serve different purposes. The original source helps explain the record's provenance; the provider can clarify the practical question you need answered.

The directory's current source context names CVTI school and counselling information, the social-service register and regional health registers. Being listed in one source does not establish every service a person might associate with a broad category.

Our studio source discussion explores a related principle in another context: evidence should answer the claim actually being made.

A model family lookup

Imagine a parent finds a service in the right region. The record was loaded recently, but its source observation is older and it does not show provider confirmation.

The useful next step is to identify the unresolved practical questions. Does this service accept the relevant age group? Is the contact current? Is the requested service offered, and how is an appointment arranged?

This is an original model example, not a report about an individual family. It describes preparing a lookup and a conversation. It is not clinical advice or a recommendation for a named provider.

Treat availability as a separate question

A register may include a vacancy figure or an availability note. The directory explicitly accompanies reported vacancies with a reminder to confirm availability with the provider.

A number in a register has a context and date. It should not be read as a reserved place or a promise that an appointment is available at the moment someone travels there.

Likewise, an unknown contact or capacity is not a zero. Keep the difference visible while deciding what to verify. This is especially useful when comparing records with different levels of detail.

Report a correction precisely

If a public record seems outdated, identify the field and the source of the discrepancy. “This contact appears different on the provider's current site” is more useful than a general claim that the whole directory is wrong.

The directory provides a provider confirmation or correction route. This article does not submit a correction or claim that a provider has approved any field. It describes the public information flow inspected on 27 November 2026.

Sources and next step

Sources: the live TAMITOS directory, its deployed record presentation and published source context, reviewed on 27 November 2026. No appointment, provider response or beneficiary outcome was tested.
